## Findings

1. P1 — Detached server reads of a received client terminal are incorrectly treated as background controlling-terminal reads. Socket snapshot src/kernel.js:3570-3577 and :5009-5018. These branches compare the caller pgid with the descriptor terminal's fgPgid without first checking that it is the caller's controlling terminal/session. SETSID clears pcb.tty, but SCM_RIGHTS correctly preserves o.tty, so the receiver can still enter this branch with pcb.tty=null. Concrete trigger: fork a server, setsid(), receive the client's terminal fd, then read it while its fgPgid remains the client's group. The code sends SIGTTIN/EINTR, or EIO when SIGTTIN is ignored/blocked, instead of reading client input. This is an inherited core behavior exposed by descriptor transfer, not a newly introduced conditional. Both the immediate read and parked-reader recheck need the controlling-terminal guard. This is a source-derived blocker for the conventional detached tmux server design; tmux was not executed in this review.

2. P2 — TIOCGWINSZ ignores the received descriptor and reports the worker's startup terminal size. Socket snapshot src/host.js:5363-5379 (services snapshot :5339-5355), called by libc/include/sys/ioctl.h:32-43. The implementation never uses fd; it reads self._stdinCtrl or returns 80x24. SCM_RIGHTS installs only the received OFD/descriptor; it does not replace that startup SAB. Concrete trigger: a server receives a terminal fd for a different-sized PTY/client, or reads a newly created pane PTY after setting its size; ioctl succeeds with the worker's original dimensions. TIOCSWINSZ and termios already resolve descriptors kernel-side, so the get-size path is inconsistent. Inherited baseline gap relevant to multiple clients, resize and reattach, not an execution-observed tmux failure. Route the query through the descriptor's terminal as well.

3. P2 — New public APIs are missing from shared-libc dynamic lookup. Services snapshot libc/include/sys/file.h:6, libc/include/sys/eventfd.h:8-10, libc/include/semaphore.h:15 and :26; build evidence src/compile.js:140-164, src/objects.js:157, :277, :828-836; lookup src/dynamic-loader.js:1167-1180. Source search finds no libc source (or transitive header include) declaring flock/eventfd through their new headers: adding those header files to the manifest does not add their imports to libc.a/libc.so.1. sem_unlink and sem_timedwait are only static inline definitions and therefore do not supply public dynamic symbols. A caller doing dlsym on libc for these names, without its own direct import publishing them, has no provider. sem_open/sem_close do have external definitions in __semaphore.c. This is a source-derived export omission, not a claim that direct header-compiled calls fail or that an existing published binary broke. Include the new host declarations in a canonical libc translation unit and provide public entry points where dynamic lookup is intended; confirm actual shared artifacts with a narrow symbol probe when a lane is available.

4. P2 — Failed fork-child initialization leaks cloned named-semaphore handles. Services snapshot src/kernel.js:2349 and :2608-2615; src/ipc-services.js:113-121. _spawnImage clones handle counts before creating the worker. The synchronous createWorker catch releases them, and normal exec/exit do too. But an asynchronous 'crashed' message while pcb._forkReady is set terminates the worker, closes fds, deletes the PCB and returns without _ipc.release(pcb.pid). Concrete trigger: parent has a named semaphore open, child initialization crashes before fork-ready, then parent unlinks/closes the semaphore. The failed child's handle map and positive refs remain, so collect cannot reclaim the unlinked semaphore; repeated failed forks accumulate phantom references. Add service cleanup to this special failure path (or share common failed-child cleanup). No fault-injection execution was performed.

## Requested areas with no additional defect established from this source pass

- Queue roots versus service waits: sockets src/kernel.js:4344-4360 roots OFDs with refs > inflight, then traverses receive queues and pending accepts. Services src/ipc-services.js:12-21 retains a blocked flock/eventfd OFD with an ordinary reference. These references are not marked inflight, so the socket collector does not mistake them for exclusively queued rights. Queued rights to a locked file also retain its OFD and therefore its flock. This is an integration inference from two separate source trees, not a merged runtime test.
- SCM_RIGHTS receive allocates references before dropping queue references; MSG_PEEK retains queued rights and duplicates received descriptors; MSG_CTRUNC drops undelivered queue references on consume. Blocked socket operations retain their socket and send-rights references; cancellation drops these. Normal exit cancels main/thread waiters before descriptor release. No additional lifetime failure established in those paths.
- Packet truncation: sockets src/kernel.js:4303-4339 bounds copied bytes, consumes the whole first packet, sets MSG_TRUNC for short buffers, and returns original packet size only for the input truncation flag. libc/include/sys/socket.h:102-118 rejects oversized packet sends and bounds scatter copy to the allocation even when returned length exceeds copied length. No truncation defect established; zero-length packets are represented by control records and count as readable.
- flock holders are keyed by OFD id, not pid; dup/fork and SCM_RIGHTS share the same OFD. Final OFD release removes ownership. Conversion drops the previous lock, and fcntl record locks are separate. No additional shared-ownership defect established.
- Named semaphore thread channels inherit the process pid/fd table (services src/kernel.js:2489-2520), while carrying their own waiter, so services' pid-indexed handles are shared across threads. The local pointer cache is locked; fork takes that lock before the allocator lock and before parking siblings. Normal fork, exec and exit hooks are present; finding 4 covers the missed failure path. Existing pthread cancellation is explicitly unsupported, so this is not claimed to implement it.
- sem_t remains a single int. Old nonnegative unnamed values and the old atomic operations remain representable. This supports source-level layout continuity only; unchanged published binaries/objects were not run or relinked. Old inlined semaphore code does not understand newly introduced negative named handles, so this is not a claim that a new named object can be passed into arbitrary unrecompiled old inline semaphore routines.
- eventfd writes still require exactly eight bytes (services src/ipc-services.js:80), consistent with the user-provided native write16 -> EINVAL observation. No contrary finding based on recollection, and that native result was not re-executed here.
